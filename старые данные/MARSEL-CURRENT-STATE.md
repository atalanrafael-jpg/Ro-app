# MARSEL / RO App — Current Control State

Дата фиксации: 2026-08-12

## 1. Рабочий контур

Текущий бизнес-контур проекта ограничен **ремонтом ювелирных изделий**.

Производство и продажи в рабочую базу не вносятся, не отправляются и не активируются без отдельного подтверждения.

## 2. Что подтверждено

- RO App API использует `https://api.roapp.io/v2`.
- Для API-аудита применяется Bearer API key через GitHub Secret `ROAPP_API_KEY`.
- READ-only аудит использует GET-запросы.
- В проекте присутствует V20.20 master audit для `GET /orders`.
- V20.20 формирует snapshot, JSON-отчёт и SHA-256 manifest.
- V20.20 явно фиксирует `mutation_allowed=False`, `WRITE_REQUESTS_MADE=0` и `RO_APP_DATA_MUTATED=False`.
- Ранее подтверждённая контрольная точка V20.8: 6 820 записей и 6 820 успешных detail-запросов, `DETAIL_FAILURES=0`, `WRITE_REQUESTS_MADE=0`.
- Заказы ранее проходили отдельный аудит с 4 373 уникальными идентификаторами и без дублей ID.

## 3. Что НЕ считать завершённым

До получения нового фактического результата нельзя считать подтверждёнными:

- полный backup всей рабочей базы RO App;
- полную endpoint matrix;
- массовое исправление данных;
- массовую синхронизацию;
- полное внедрение ERP-конфигурации в рабочий аккаунт;
- автоматический расчёт себестоимости в рабочем аккаунте.

## 4. Безопасный порядок

`READ-ONLY API → актуальный snapshot → проверка целостности → DATA AUDIT → dry-run → тестовая корректировка → проверка → только затем разрешённые изменения`.

## 5. Запреты текущего этапа

Нельзя выполнять `POST`, `PUT`, `PATCH` или `DELETE` против рабочего RO App из audit workflow.

Нельзя считать CI `success` доказательством успешной синхронизации, если отсутствует фактический HTTP-результат API.

Нельзя считать старые MASTER-реестры актуальными без сверки с более новыми фактическими результатами.
